## Drift log

All three root causes below were verified by an adversarial code-review pass (investigate →
refute); none were refuted.

1. **Route details page renders static demo content for generated routes** (FR-8/FR-12 surface).
   The record data is correct and complete, but the page shows the 6 hardcoded demo stops
   (Nordhavn Depot → … → ARC Amager, statuses Completed/Next) instead of the route's pickups,
   static Schedule/Progress values ("Actual time 06:10 → In progress", "2 of 6", "3.8 t")
   nonsensical for a future Planned route, and does not render the record facts Depot, Unloading,
   Time window, Scheme version, or Deviation (`11-route-detail.png`). Root cause:
   `components/wastehero/route-details-page.tsx` is the demo-era view — OverviewTab seeds its
   stop table from the hardcoded `initialStops` array (lines 92–147, `useState(initialStops)` at
   433) and RouteInformation hardcodes Schedule/Progress rows (351–362) with "Completed stops"
   computed from those same demo stops (320–322). It receives no pickups
   (`business-workspace.tsx:3934–3956`), although the exact lookup already exists in the same file
   (ReassignRouteDialog's `useModuleRecords("route-studio","pickups")`, line 219, filtered by
   `routeId` per `generation.ts:536–539`). The generated facts (written at `generation.ts:713–732`)
   are rendered nowhere — RouteInformation reads only Vehicle/Driver/Trailer/Service provider (334–350)
   and the generic all-facts renderer is bypassed for routes (`business-workspace.tsx:1225–1228`).
   Minimal fix stays inside `route-details-page.tsx`.
2. **Edit route dialog loses current values on generated routes** (FR-12). "Edit route" on
   RC-9145 opened with Date* empty and Vehicle*/Driver* on placeholders. Root cause: a key
   mismatch — `editInitialValues` (`business-workspace.tsx:2296–2316`) seeds the dialog from
   `record.submittedValues`, but generation writes `serviceDate`/`actualDate`/`appliedVehicle`/
   `appliedDriver` (`generation.ts:747–755`) while the routes schema fields are
   `projectId`/`operatingDate`/`vehicleId`/`driverId` (`business-form-schemas-operations.ts:44–87`)
   — only `schemeId` intersects, so only Route Scheme genuinely prefills. Two verified extras:
   (a) Project "prefilling" is an illusion — it comes from the workspace's default project scope,
   so editing a Harbor route would wrongly show Copenhagen; (b) required-field validation blocks
   save until Date/Vehicle/Driver are re-picked (risking accidental reassignment), and a save then
   adds new label-keyed facts ("Date", "Route Scheme") beside the stale generated ones
   ("Operating date", "Route scheme") while `submittedValues.serviceDate` — the route's identity
   key at regeneration (`generation.ts:292–295`) — keeps the old date.
3. **Chooser copy says "route"** on the scheme flow: "Choose how you'd like to set up your route"
   / "Create a route with minimal setup" (`01-chooser.png`). The strings are hardcoded in the
   shared `components/project-wizard/steps/StepMode.tsx` (lines 66/83), rendered by three flows
   (scheme, route, legacy project wizard), so the fix is a copy prop (e.g. `entityLabel`
   defaulting to "route") passed from `scheme-create-flow.tsx:291` — not a blind string edit.

  calendar-working-days layer.
